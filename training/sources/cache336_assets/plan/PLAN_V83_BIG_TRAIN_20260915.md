# Большой цикл v8.3: две RTX 5090, локальные армы и LB-гейты

Версия плана: 3  
Дата фиксации: 2026-09-15 (Europe/Moscow)  
Бюджет: не более $30, из них $4 сохраняются как резерв до окончания подтверждённых задач.

## 1. Цель и неизменяемые правила

Цель цикла — впервые обучить глобальный AUX60 на `knee-laterality-v8.3`, затем проверить источники разнообразия, которые могут дополнить CoAtNet: локальные анатомические входы, Native64-v2, фазовый TTA, severity-метки и matched R5.

Текущая подтверждённая публичная точка отсчёта — submission `56236084`, public LB `0.948`: legacy AUX60 full + compartment main4 + R5 full с весом 30% на остальных восьми таргетах. Это контроль старого входа.

Для всех новых запусков цикла фиксируются:

- `knee-laterality-v8.3`, каноническая ориентация `canonical_L_v8_3` и общий runtime, экспортированный `scripts/prepare_orientation_runtime.py`;
- soft-v2: 4 352 `SampleID` из 4 345 родителей, 4 350 активных main12-строк; семь bilateral-исследований остаются в своём parent/report-group;
- Gold58 строится тем же pixel/cache builder для каждого семейства входов, но хранится отдельным `validation-only` split, не входит в loss и не выбирает эпоху;
- CoAtNet: schedule 24, stop 20, фиксированное среднее эпох 18–20;
- на fold-запусках после каждой эпохи 1–20 считаются pseudo fold и Gold58; на full-fit после каждой эпохи считается Gold58; финально отдельно оценивается среднее 18–20;
- метрики и bootstrap считаются на parent/report-group grain; для bilateral-parent два колена агрегируются максимумом по таргету, отдельно сохраняется sample-level диагностика;
- исторические кэши в старой канонической ориентации не переименовываются в v8.3 и не переиспользуются как новые пиксели.

### 2.2. Новый storage-план

| Артефакт | Оценка | Статус оценки |
|---|---:|---|
| Full-source bank Native64-v2 | 64.8 ГБ | измерено |
| Compartment v8.3, 90 мм / 384 px | 52–58 ГБ | 50.62 ГБ измерено на прежней версии |
| Общий anterior A/B superset | 24–32 ГБ | инженерная оценка; старый v1 = 17.22 ГБ |
| Ligament v8.3 | 18–25 ГБ | инженерная оценка до пилота |
| Gold58 для всех cache-family | 1–3 ГБ | validation-only, точный объём после pilot |
| Метки, индексы, QA | <1 ГБ | табличные данные |
| Итого производных данных | 161–184 ГБ | без сырого DICOM |

Требование к Vast:

- **250 ГБ — допустимый жёсткий минимум при поочерёдной загрузке и удалении уже использованного кэша**;
- **300 ГБ — предпочтительно**, 350 ГБ даёт дополнительный запас;
- 600 ГБ не требуется, если сырые DICOM-шарды скачиваются, распаковываются, преобразуются и удаляются последовательно, а A/B используют общий superset cache;
- перед распаковкой следующего шарда `disk_free >= 25 GiB`; не хранить одновременно архив, распакованный DICOM и вторую копию кэша;
- одновременно держим только кэши текущей волны; использованный кэш остаётся в приватном Kaggle-артефакте и удаляется с GPU-диска после hash-verified checkpoint backup;
- на 250-ГБ диске hard-stop срабатывает при `disk_free < 25 GiB`; checkpoints, окружение и рабочие файлы должны укладываться примерно в 20–30 GiB.

600 ГБ имели бы смысл только для одновременного хранения полного сырого DICOM (~143–200 ГБ), всех распакованных копий и дублирующихся A/B-кэшей. Такой маршрут не нужен.

### 2.3. Kaggle CPU-подготовка

Официальное ограничение notebook output — 20 ГБ. Поэтому большой кэш не публикуется одним dataset:

1. маленький приватный asset dataset `ilyakolb/rsna-v83-cache-assets-20260915` содержит runtime v8.3, soft-v2, operations, Gold58 validation manifest/labels, locators, specs, shard-map и хеши;
2. приватный CPU smoke kernel `ilyakolb/rsna-v83-cache-smoke-200-20260915` проверяет 200 train-parent, исключая fold 3 и Gold;
3. после smoke PASS число production-шардов выбирается по измеренному объёму: минимум 8, каждый hard-stop до 18 ГБ output;
4. запуски идут по 2–4 CPU kernel одновременно, насколько позволяет актуальная Kaggle quota;
5. Vast скачивает outputs параллельно, сверяет SHA256 и удаляет транспортные архивы после распаковки;
6. существующий 64.8-ГБ source bank переносится отдельно в 8 потоков; заново через Kaggle не считается.

Smoke использует 200 train-parent без fold3/Gold и отдельно все 58 Gold как validation-only. Он проверяет cardinality, отсутствие train/Gold overlap, `train_mask=0` для Gold, наличие DICOM/series/SOP, применение v8.3 operations ровно один раз и прогноз размера. Он не выдаётся за готовый production cache.

Каждый production cache release обязан содержать два namespace: `train/` и `gold58/`. Для Gold используется тот же размер поля зрения, выбор серий, ориентация v8.3, нормализация и формат массива, что и для train. В `CACHE_COMPLETE.json` отдельно фиксируются `gold_studies=58`, формы, число файлов, байты, SHA256 и нулевое пересечение с обучающим split. Релиз без полного Gold58 не допускается к обучению.

## 3. Параллельность двух RTX 5090

### 3.1. Десятиминутный throughput-probe

До основного запуска измеряются три режима на одинаковых 200 batch:

1. одна модель на одной GPU;
2. две независимые модели, по одному процессу на GPU;
3. DDP одной модели на двух GPU с неизменным effective batch и числом optimizer steps.

По умолчанию выбираются два независимых процесса. CoAtNet использует BatchNorm; простое удвоение GPU меняет per-GPU batch и статистики, поэтому DDP допускается только при совпадении лосса/логитов на коротком фикстурном тесте и ускорении не меньше 1.5x. Если нет — каждый fold/arm занимает ровно одну карту.

### 3.2. Почему фазовый TTA не стартует в нулевую минуту

Решающая TTA-проверка использует готовые fold-3 предсказания AUX60-v8.3, поэтому до среднего 18–20 её считать нечем. Чтобы карта не простаивала, в это время на второй GPU идёт anterior A. Сразу после готовности baseline GPU0 выполняет фазовый инференс (около 15–25 минут), пока GPU1 продолжает обучение.

## 5. Гейты по веткам

### 5.1. AUX60-v8.3

`AUX60_V83_F3` — обязательный новый baseline. Сравнение с legacy AUX60 f3 на общем parent-grain:

- pseudo macro не хуже −0.003;
- unchanged subset и within-site не хуже допустимого шума;
- per-target, bilateral sample-level и Gold58 публикуются описательно;
- после каждой эпохи сохраняются prediction CSV, macro/per-target/within-site и Gold58; эпоха не выбирается по этим значениям, итог всегда 18–20.

PASS открывает full-fit и служит базой всем новым бленд-гейтам.

### 5.2. Phase-TTA

На fold3 AUX60-v8.3 строится сдвинутая решётка P0.5 без обучения. Сравниваются P0, P0.5 и rank-mean 50/50. Включение в inference kernel только если:

- delta macro >= +0.001;
- report-group bootstrap CI95 целиком выше нуля;
- нет материальной просадки weak4 и within-site.

Иначе TTA закрывается и не удваивает LB-инференс.

### 5.3. Compartment full-fit

Предыдущий fold3 уже прошёл гейт на legacy-входе. В этой поездке обучается запланированный full-fit на v8.3/soft-v2, 4 243 доступных parent плюс корректная обработка bilateral samples. Перед LB нужен sanity against old full and hash-verified identity.

### 5.4. Передний отдел и синовит

Ветка считается приоритетной после baseline, потому что текущие текстовые метки синовита подозрительно зависят от площадки, а Gold показывает просадку.

Нулевая проверка уже выполнена на готовом anterior-v1 R5: PF OA rank-blend 70% AUX60 + 30% anterior даёт +0.008583 на fold3, CI95 `[+0.002023; +0.015338]`. Поэтому старый v1 сохраняется как PF-OA-only кандидат; это не подтверждает новый crop-рецепт для синовита.

Новые армы:

- **A, контроль разрешения:** прежняя геометрия v1, CoAtNet-384, рецепт AUX60, 48 окон, k=12;
- **B, карманы:** тот же вход плюс 50×50-мм axial recess при 7.7 px/mm и периферические sagittal 90×90 мм; квоты 18/10/8/12; metadata 11;
- A и B читают один общий superset cache;
- серия выбирается по минимальному `PixelSpacing`; тонкие 3D серии используют нативный triplet без slab.

Гейты:

- диагностический A: solo main3 >= AUX60-v8.3 −0.010; FAIL закрывает локальный anterior input;
- членство A: rank50 средний delta по PF OA/Effusion/Synovitis >= +0.004 с CI95 > 0, Synovitis >= +0.004, within-site не хуже;
- B над A: delta Synovitis >= +0.004 с CI95 > 0 и Synovitis AUC внутри Effusion+ выше A;
- обязательно считать Synovitis отдельно внутри Effusion+ и Effusion− на population и описательно на Gold58;
- Gold58 не выбирает эпоху или арм, но противоречащая pseudo/LB просадка запускает аудит меток.

Предварительное правило по LB synovitis-пробе: `>=0.86` — после crop-теста ветку меток заморозить; `0.78–0.86` — идти в label/PU этап; `<0.78` — label/site-PU становится приоритетнее wave 2.

### 5.5. Native64-v2

Использует существующий проверенный 64.8-ГБ source bank и отдельный v8.3 namespace. Fold3 гейт:

- solo >= AUX60-v8.3 f3 −0.001;
- rank50 blend delta >= +0.003 с CI95 > 0;
- Spearman <=0.93.

PASS открывает full-fit. FAIL сначала разбирается по компонентам; второй безразборный перезапуск запрещён.

### 5.6. Matched R5-v8.3

R5 выбран вместо R4: исторический R5 уже имеет 4 345×60 five-fold OOF и дал полезный rank30-сигнал, тогда как R4 не прошёл blend-гейт. Новый `R5_V83_F3` меняет только вход/manifest на v8.3/soft-v2 и сохраняет RadImageNet ResNet50-224, schedule 48 / stop 40 / average 38–40.

Историческая отправная точка R5 f3: solo 0.892405, Spearman 0.852942, rank30 delta +0.002097 с CI95 `[+0.000211; +0.003878]`; именно поэтому R5 30% вошёл в public 0.948. Новый matched probe нужен, чтобы понять, сохраняется ли разнообразие после v8.3.

R5 не дублируется на каждом 384-пиксельном локальном кропе: это смешает проверку геометрии с другим разрешением/backbone. Для label-only severity/Core5+ matched R5 запускается условно после PASS CoAtNet, а его five-fold расширение относится к C2.

Гейт R5-v8.3:

- rank30 blend с AUX60-v8.3 >= +0.0015 и CI95 > 0;
- Spearman <=0.93;
- weak4 либо средний main12 не хуже исторического направления.

### 5.7. Severity

Сначала `TGT_F3`, затем `WGT_F3` только если первый результат не отвечает на гипотезу. Untouched-macro должен улучшиться минимум на +0.004 с CI95 > 0. PASS открывает full-fit победителя. Вход и ориентация идентичны AUX60-v8.3.

### 5.8. Связочный арм

Локатор фиксируется до GPU:

- notch_x: sagittal condylar-band profile с полярностью по FS-тегу, усреднённый с серединой sagittal stack;
- coronal x-profile остаётся информационным и не голосует;
- MCL ROI привязан к notch, не к коже: медиально `notch−80 мм`, латерально `notch+30 мм`, по z `joint_z−65…joint_z+45 мм`;
- 48 окон: sag notch FS 10 + non-FS 8, cor notch 6, oblique 4, cor MCL FS 8 + non-FS 6, sag MCL 6;
- main: ACL/MCL; 10 aux — подтипы ACL/PCL/LCL/MCL и связанные структурные находки из спецификации;
- если более 5% population имеют расхождение profile и midpoint >15 мм, до обучения добавляется третий `joint_gap`-голос.

Гейт rank50 с AUX60-v8.3: ACL >= +0.003, MCL >= +0.006, среднее >= +0.005, все соответствующие CI95 > 0, Spearman <=0.90. Только PASS открывает full-fit.

## 6. C2 и ансамбль

Исторический R5 OOF уже полностью готов: 4 345×60, пять исходных folds. Он может входить в offline nested-weight анализ сразу, с явной пометкой legacy-input.

После основных PASS-армов C2 добавляет одинаковые f0/f1 для AUX60-v8.3, compartment и Native64-v2. Это даёт около 2 600 совместимых OOF parent на f0/f1/f3. Если R5-v8.3 проходит, его f0/f1 также добавляются в C2; иначе используется только уже готовый legacy R5 как фиксированный comparator.

Per-target веса выбираются nested CV. Compartment, anterior, ligament и R5 могут получать вес только на соответствующих таргетах. Ветка старого CoAtNet R остаётся фиксированным diversity comparator; новый full/folds R не запускаются до доказанного выигрыша поверх v8.3 ансамбля.

## 7. Бюджет и стоп-правила

Оценка главного маршрута с per-epoch validation — 57–62 GPU-hours. Для двух-GPU предложения:

- при общей цене до $0.75/ч 31 час стоит около $23.25;
- трафик/диск оцениваются в $2–3;
- $4 не расходуются до подтверждения обязательных задач;
- общий ожидаемый предел — $29–30.

Предложение дороже $0.75/ч за обе карты допускается только после пересчёта очереди. До каждой условной full-fit задачи создаётся свежая проекция: если выполненные расходы + ожидаемая задача + $4 резерва превышают $30, задача не стартует. C2 не входит автоматически в исходные $30 и начинается только на высвободившемся времени или после отдельной проекции.

## 8. Критерий готовности к аренде

Аренда начинается после всех пунктов:

1. orientation export и soft-v2 hashes PASS;
2. Kaggle smoke-200 COMPLETE/PASS;
3. pilot даёт projected shard output <18 ГБ и итог производных данных <=184 ГБ либо план пересчитан;
4. production cache outputs скачаны или имеют проверенный параллельный маршрут на Vast;
5. найдена 2×RTX5090: диск >=250 ГБ при streaming-cleanup либо >=300 ГБ без него, RAM >=64 ГБ, CPU >=32, надёжность >=98%, DLPerf/$ >=250, общая цена предпочтительно <=$0.75/ч, дешёвый входящий трафик;
6. clean CUDA smoke, обе GPU видны, независимые процессы держат обе карты, checkpoint/backup path проверен;
7. exact task queue и cost guard записаны на сервер.

## 9. Сила выводов

- Измеренные размеры, исторические OOF/LB и PF-OA bootstrap — наблюдения.
- ETA новых армов, размер anterior/ligament и будущий LB uplift — инженерные оценки.
- Ни Gold58, ни один fold3 не доказывают улучшение LB; решение принимает совокупность заранее заданного fold-гейта, sanity-разрезов и разрешённого LB readback.
