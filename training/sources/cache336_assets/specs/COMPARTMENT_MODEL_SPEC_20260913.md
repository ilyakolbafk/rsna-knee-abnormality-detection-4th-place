## 0. Зачем и на что рассчитываем

- Слабые таргеты по image-based истине (Gold58, AUX60 fold 3 / пятёрка): Lateral OA 0.82, Lateral Meniscus 0.88, PF OA 0.85, Synovitis 0.78; медиальные аналоги 0.98 / 0.98. По pseudo на fold 3: Lat OA 0.874, Lat Men 0.901 против Med OA 0.906, Med Men 0.959. Латеральных позитивов вдвое меньше (Core5: Lat OA 856 против Med OA 1434), отчётная метка по латеральному OA сама слабее против Gold (0.865 против 0.933).
- Разрешение: текущий вход — окно ≈ 140 мм в 336 px (2.4 px/мм); хрящ 2–4 мм = 5–10 px, частичная потеря толщины 1–2 мм = 2–5 px. Кроп компартмента ≈ 65–90 мм в 384 px даёт 4.3–5.9 px/мм — ×2–2.5 на хрящ и мениск. Кропить **только из сырых DICOM**: ROI из уменьшенного кэша уже проигрывал глобальному входу (0.755 против 0.855; `rsna-knee-roi-upscale-20260906`).
- Литература: Tack 2021 (OAI, 2 399 DESS) — кроп по менискам 0.74–0.94 → 0.87–0.95; RSNA 2024 / 2025 призовые решения — локализация → кроп.
- Два усилителя, которых нет у глобальной модели: **зеркалирование** (одна модель на оба компартмента с флагом стороны — латеральные находки учатся на форме, выученной и на медиальных позитивах) и **локализованная супервизия** из aux48 (хрящ по поверхностям, BME по локализациям, зоны мениска, экструзия) — для компартментной модели это её родные метки.
- Ожидание: +0.02…+0.05 AUC на Lat OA / Lat Men по image-based истине, если сработает; в ансамбле — только на этих таргетах; LB +0.002…+0.005. Риск средний, цена — инженерия кэша, GPU ≈ 4–5 ч на fold 3.

## 1. Гипотеза и гейт (фиксируются до запуска)

H: компартментный вход в нативном разрешении с зеркалированием повышает ранжирование латеральных таргетов относительно AUX60 fold 3 на тех же 870 held-out.

Гейт продолжения (folds / full / член ансамбля), все условия вместе:
1. Rank-бленд 50/50 «AUX60 ⊕ компартмент» на четырёх таргетах (Med Men, Lat Men, Med OA, Lat OA) — средний прирост ≥ +0.005, парный report-group bootstrap CI > 0.
2. **Оба латеральных** таргета в бленде ≥ +0.005 каждый. Если растёт только медиальное — рычаг не тот, что думали; фиксируем как отрицательный.
3. Within-site на 870 не хуже AUX60 на этих четырёх.
4. Gold58 (компартментный кэш для Gold строится отдельно, Gold вне fit) — диагностика, не голосует.
Solo ≥ AUX60 не требуется: модель узкая, её место — бленд по четырём таргетам.

## 2. Геометрия компартментов (правило, без обучаемой сегментации)

Используются существующие модули, но с другой приёмкой. **Сторона** — из сохранённого определения Native64 (`Gold58_native64_side.csv` для Gold, манифест Native64 для population: тег `Laterality`/описание серии, иначе геометрия; при конфликте — тег, как в Native64): известна у 55/58 Gold и 4 246/4 345 population. Строгий `infer_knee_laterality` с отказом геометрии без тега не применяется. `anatomy_roi.normalised_lateral_positions` — центры сагиттальных срезов → [0, 1] медиально→латерально (правило `lateral_coordinate`: x для L, −x для R). **Высота щели** — по § 2.1 (согласие двух плоскостей вместо порога 0.80 на балл `joint_line_locator`; `route_lateral_crop` с этим порогом не используется). Всё считается в координатах пациента из DICOM, пиксели — из сырых серий.

### 2.1. Высота щели: правило и приёмка (перенести из прототипа `scripts/compartment_locator_v1.py`)

- **Профиль**: интенсивность вдоль S-I оси пациента, усреднённая по центральной полосе кадра (40 % ширины); z каждой строки — с учётом наклона плоскости по **обоим** направляющим векторам IOP (без этого косые коронарные дают систематическую ошибку до 15 мм). Срезы-кандидаты: мыщелковые сагиттальные (нормированная позиция 0.15–0.40 и 0.60–0.85) и центральные коронарные (0.30–0.70 по A-P). На срезе ищется самый глубокий провал между двумя костными плато: сглаживание 6 мм, нормировка p5/p99, оба плато ≥ 0.45 в пределах 45 мм, поиск в центральных 70 % профиля.
- **Полярность** (костный мозг яркий на PD/T1 без FS, тёмный на FS/STIR/T2-GRE) — **по данным, не по тегу**: на каждую серию считаются оба варианта; остаются когерентные опции — ≥ 3 срезов с MAD ≤ 6 мм. На Gold полярность, выбранная по данным, расходится с тегом FS у 2 сагиттальных и 9 коронарных серий.
- **Выбор на уровне исследования**: среди когерентных опций сагиттальных и коронарных серий — пара с минимальным |z_sag − z_cor| (+ 0.5·(MAD_sag + MAD_cor) + 2 мм штрафа за полярность ≠ тег FS). Согласие ≤ 10 мм → `joint_z` = среднее, `accept = both_planes_agree`; расхождение > 10 мм → z сагиттальной, `accept = planes_disagree_use_sag`; одна когерентная плоскость → её z, `accept = single_plane`; ни одной когерентной опции → `accept = none` (исключение). На Gold: 52 / 2 / 4 / 0.
- **Per-компартментный z**: `z_medial` / `z_lateral` — медианы по сагиттальным срезам своего компартмента (позиция < 0.5 / ≥ 0.5); использовать при |z_medial − z_lateral| ≤ 10 мм (на Gold медиана 3.1 мм, p90 7.4 — наклон колена реален), иначе общий `joint_z`. `notch_x` — середина размаха центров сагиттального стека по латеральной координате.
- **Выходы кэша на исследование**: `side, side_source, joint_z, z_medial, z_lateral, notch_x, accept, sag_cor_gap, polarity_sag, polarity_cor, n_slices_sag_med, n_slices_sag_lat`.
- **Допуск**: кроп 90 мм по вертикали переносит ошибку высоты ±15 мм без потери мыщелка и плато, поэтому порог на внутренний балл и требование согласия соседних срезов не применяются. Реализация на population — с pydicom на инстансе (прототип читает только Explicit VR LE без сжатия; долю сжатых transfer syntax на population проверить и записать в QA).

- **Сагиттальные срезы компартмента**: медиальный — нормированная латеральная позиция ∈ [0.00, 0.42], латеральный — ∈ [0.58, 1.00]; зона 0.42–0.58 (межмыщелковая вырезка, ACL/PCL) исключена из обоих. Внутри среза — квадрат 90 × 90 мм, центр по вертикали на z суставной щели, по горизонтали — центр кости в среза (медиана маски ненулевого сигнала); ресемпл до 384 px (≈ 4.3 px/мм). Без in-plane отражения: передне-задняя ориентация уже канонизирована текущим side-transform.
- **Коронарные половины**: кадр делится по X патиента в точке межмыщелковой вырезки — берём X, соответствующий нормированной латеральной позиции 0.5 сагиттального стека (середина его размаха); при отсутствии сагиттального стека — центр текущего центрального кропа. Кроп — квадрат 90 × 90 мм с сохранением масштаба (без анизотропного ресемпла): по горизонтали от точки «вырезка + 20 мм в сторону противоположного отдела» на 90 мм в сторону своего компартмента (то есть 70 мм компартмента + 20 мм захода на вырезку), по вертикали — центр на z суставной щели; ресемпл до 384 × 384 (≈ 4.3 px/мм). **Латеральную половину отражаем по горизонтали**, чтобы вырезка у обоих компартментов была с одной стороны кадра (зеркалирование).
- **Аксиальные** для тибиофеморальных компартментов не используются (в первом арме).
- **Исключение** — только при неизвестной стороне (Native64: 3/58 Gold, ≈ 99/4 345 population) или при `accept = none` (на Gold — 0). Целевое покрытие: ≥ 95 % population и ≥ 55/58 Gold с кропами. Ниже — стоп, разбор причин по монтажу, не запускать GPU. Fallback на центральный кроп по-прежнему нет: исключённые исследования на четырёх компартментных таргетах получают только AUX60.
- Окна на один компартмент-сэмпл: **48 триплетов** (соседние срезы по `central_sampling.source_triplets` с ограниченным пулом центров): сагиттальные FS 14 + non-FS 14 (из срезов компартмента), коронарные FS 10 + non-FS 10 (половины). Квоты — как в Native64 (water-filling по доступным сериям), trim не нужен (пул уже ограничен). Метаданные окна — те же 6 acquisition-признаков + **1 признак «компартмент латеральный» (0/1)** → проекция метаданных 7 → d.

## 3. Сэмплы и метки

Единица обучения — пара (исследование, компартмент ∈ {medial, lateral}); из 4 345 исследований — до 8 690 сэмплов на фолд-фит (минус исключённые). Одна модель на оба компартмента.

Головы компартмента (14), метки берутся у соответствующей стороны:

| Голова | Медиальный сэмпл ← | Латеральный сэмпл ← |
|---|---|---|
| meniscus_tear (main) | Medial Meniscus | Lateral Meniscus |
| compartment_oa (main) | Medial OA | Lateral OA |
| collateral_ligament | MCL | lcl_plc_injury (aux) |
| meniscus_anterior / body / posterior / root_tear, extrusion, intrasubstance (6 aux) | medial_meniscus_* | lateral_meniscus_* |
| cartilage_femoral_grade2plus, cartilage_tibial_grade2plus (2 aux) | cartilage_medial_* | cartilage_lateral_* |
| bme_femoral, bme_tibial (2 aux) | bme_medial_* | bme_lateral_* |
| parameniscal_cyst (aux) | parameniscal_cyst | parameniscal_cyst |

Глобальные таргеты (ACL, PF OA, Effusion, Synovitis, Baker's, Contusion, Fracture) в компартментную модель **не входят** — она их не видит целиком и будет учить артефакты. Лосс — как в AUX60: masked BCE с pos_weight для main (2), взвешенное среднее для aux (12) с `aux_weight` 0.25, веса клеток confidence × mask, presence-only `parameniscal_cyst` — как есть. pos_weight — по train-части фолда, отдельно для этой модели (у неё другая population сэмплов), зафиксировать в POS_WEIGHT.json.

Версия меток: **та же, что у контрольного AUX60 fold 3 (Core5 + aux48 исходные)** — чтобы сравнение было про вход, а не про метки. Core5+/Aux60+ на компартментную модель переносить отдельным шагом после гейта.

## 4. Модель и рецепт

Backbone `coatnet_rmlp_2_rw_384.sw_in12k_ft_in1k` с ImageNet-12k инициализацией (не с весов AUX60 — иначе смешаем эффект входа с дистилляцией), class-attention голова на 14 запросов, softmax по окнам; k = 12 случайных окон на train-шаг, все 48 на eval; bs 8; AdamW 3e-5 / 1e-3 / wd 0.02; OneCycle pct 0.15, расписание 24, стоп 20, среднее весов 18–20; без EMA; seed 20260908; те же нормировки пикселей (0.5/99.5 по окну), что у N. Fold 3 — те же 3 475 fit / 870 held-out и report-группы, Gold58 + 4 связанных вне fit.

Время: сэмплов ×2, окон 48 вместо 64 → ≈ 1.5× шагов AUX60 → на 5090 ≈ 4–4.5 ч, на PRO4500 ≈ 10 ч. Валидация только на 5/10/15/20 и на среднем 18–20 (правило пользователя 12.09).

## 5. Оценка на fold 3 (870)

Из двух сэмплов исследования собираются 4 study-скора: Medial Meniscus ← meniscus_tear медиального сэмпла, Lateral Meniscus ← латерального, Medial OA / Lateral OA ← compartment_oa. Считать против Core5 (confidence ≥ 0.5, ≠ 0.5) — те же строки, что у AUX60 fold 3:

- соло по четырём таргетам против AUX60 (0.9592 / 0.9012 / 0.9060 / 0.8743);
- rank-бленд 50/50 по каждому из четырёх, парный report-group bootstrap (≥ 600), within-site;
- Spearman компартмент ↔ AUX60 по четырём таргетам (ожидаем < 0.9 — другой вход);
- aux-головы против своих меток (обучаемость), сравнить с aux-головами AUX60 на тех же строках (cartilage_lateral_*, lateral_meniscus_* — там, где у AUX60 0.91–0.96);
- Gold58: компартментный кэш для 58, те же 4 таргета + per-target Δ; диагностика.
Сохранить все 14 выходов на held-out и на Gold (обе стороны), IDENTITY с геометрическими параметрами.

## 9. Чего не делать

- Не кропить из кэша 336 px; не апскейлить SR-моделями (readout 06.09: демонстрация без OOF-эксперимента).
- Не обучать сегментацию/keypoint-модель без масок; правило + согласие двух плоскостей достаточны, детектор — только если визуальный QA покажет систематические промахи.
- Не возвращать порог на эвристический балл локатора (0.80) и не требовать согласия соседних срезов как условие приёмки; не отбрасывать сторону, определённую геометрией Native64, без тега.
- Не включать глобальные таргеты в головы компартмента; не подменять AUX60 на восьми остальных таргетах.
- Не инициализировать с весов AUX60; не менять версию меток относительно контроля; не подбирать границы 0.42/0.58, размеры кропов и веса бленда по Gold или по held-out после просмотра результата (одна правка границ допустима только по визуальному QA до обучения).
- Не запускать до LB A′/B′ и без подтверждённого бюджета.
